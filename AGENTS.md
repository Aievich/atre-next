# Правила работы с сайтом АТРЭ

## Область и источники

Рабочий корень — `D:\Projects\ATRE-Site`, существующий репозиторий `Aievich/atre-next`. Режим: подключение существующего проекта к практике, без реорганизации, смены дизайна и переноса чужого авторского стиля.

Перед работой читать этот файл, README.md, CHANGELOG.md, ПРОЕКТ.md, Реестр-решений.md и Отложенные-правки.md; профильные инструкции VOICE-CONTROL.md, POLYMER-VISUALS.md и content/reports/polimery-2026/README.md — по задаче. В src, scripts, tests, data, content и public не нужны дубли общих инструкций; локальные AGENTS добавлять только при появлении отдельных правил.

Фактическое расположение командного комплекта указано в ПРОЕКТ.md. Прочитать 03_Скиллы/project-practice/SKILL.md и 06_Командная практика/Правила-практики.md из указанного комплекта при задачах практики. Пользовательские инструкции и действующие решения проекта имеют приоритет. Если внешний комплект недоступен, выполнять доступные проектные инструкции и явно сообщать ограничение. Не устанавливать скиллы глобально автоматически.

## Материалы и изменения

Сохранять существующие пути и авторские правки. Не удалять, не переносить и не переименовывать накопленные материалы без поручения. Перед циклом правок обеспечить откат существующих изменений. Рабочая версия одна; новые каталоги создавать по потребности.

Править src, data, content, public и исходный index.html по назначению; dist — результат сборки, не первичный материал. Сохранять оригинальные PDF, изображения, весь текст, числа, периоды, единицы и методические оговорки. Не заполнять пропуски нулями, не выдумывать результаты, источники и параметры. Сохранять происхождение и контрольные суммы. Крупный PDF восстанавливать штатной сборкой из data/assets.

Сохранять действующие дизайн, шрифты, корпоративные ресурсы и ограничения демонстрации. Шаблоны практики, её авторский профиль и персональные речевые запреты не наследовать. Закрытые материалы, секреты и персональные данные не включать в публичный репозиторий. Noindex не является ограничением доступа.

Каждое содержательное изменение связывать с поручением или аннотацией. После существенных изменений обновлять CHANGELOG и при необходимости README; новые принятые решения записывать в реестр, незавершённое — в отложенные правки. Исторические сведения подтверждать коммитами и документами; даты файлов не использовать как доказательство этапа.

## Git и публикация

Перед правками проверить корень, ветку, status и diff. Сохранять все незакоммиченные изменения. Не выполнять повторный init, reset/clean с потерей файлов, переписывание истории, автоматическое переключение на старые локальные ветки и слепой git add -A.

Origin сохраняется: https://github.com/Aievich/atre-next.git. На дату подключения текущая ветка published/annotations-2026-11-19 отслеживает origin/design/perspective-v1. Ветку всегда проверять фактически. Не вводить другую схему веток, обязательный PR или hooks без согласования.

Коммиты выполняет пользователь по подготовленным агентом командам с явным составом файлов, пока отдельно не разрешены локальные коммиты агента. Конфигурацию Git, hooks, новые серверы, установку компонентов и push выполняет пользователь по точному блоку с последующей проверкой вывода. Ранее данное пользователем разрешение имеет приоритет, повторного подтверждения уже разрешённых действий не требовать.

Push, pull, merge и публикацию не выполнять без поручения. Push в design/perspective-v1 автоматически запускает GitHub Pages. Чтение remote через git ls-remote не меняет рабочие файлы. Локальные изменения не объявлять опубликованными до проверки deployment и build-info.json.

## Проверка и передача

Для кода и данных: node scripts/build.mjs и node --test tests/*.test.mjs, затем затронутые браузерные сценарии. Для документов: факты, ссылки и git diff --check. Не объявлять тесты выполненными по одному чтению исходников. Сборка записывает dist и .openai/hosting.json; конфигурацию не терять.

Интерфейс проверять через работающий локальный сайт и адресные комментарии в Codex. Если комментарии недоступны, дать воспроизводимый маршрут и точный элемент, назвав ограничение. Голосовые имитационные тесты не подтверждают распознавание живой речи. Не менять разрешения микрофона и внешние системы автоматически.

Перед согласованной сдачей проверить требования, данные, ссылки, отображение и состав; при доступном независимом исполнителе поручить проверку зафиксированного результата. Итоги существенного контроля хранить компактно в docs/checks; временные сборки и откат — вне публичного состава. В ответе назвать изменения, реальные проверки, непроверенное, состояние Git и следующий шаг.
